# 需求分析文档 — 万能视频下载网站

> 本文档沉淀项目的需求背景、目标用户、功能范围与边界，供后续扩展功能时为 AI / 团队提供参考。

## 1. 背景与动机

很多用户有"下载并保存视频到本地"的需求，但常遇到以下痛点：

- 部分平台不支持下载功能；
- 平台自带下载不够方便（不支持批量、有清晰度限制、有水印、需要会员等）；
- 缺少一个"随时随地、跨平台、手机也能用"的统一入口。

因此需要开发一个**万能视频下载网站**，让用户能够更快速、随时随地、从各个平台下载视频。

## 2. 项目目标

- 提供一个 **Web 端**（桌面 + 移动端浏览器均可用）的视频下载工具。
- **全平台覆盖**：尽可能支持主流平台（YouTube、Bilibili、抖音/TikTok、X/Twitter、Instagram 等）。
- **简单易用**：粘贴链接 → 选择清晰度 → 一键下载。
- **商业化定位**：界面精致、突出实用价值，引导用户付费（本期定价区块为视觉展示）。
- **轻量、低风险**：站在开源巨人肩膀上（yt-dlp），尽量少自研下载逻辑。

## 3. 目标用户

- 需要保存视频用于学习、二次创作、离线观看的普通用户；
- 自媒体 / 内容创作者（关注无水印、高清、批量）；
- 移动端用户（手机上也要能下载）。

## 4. 功能范围（本期 MVP）

### 4.1 核心功能（本期实现）

| 功能 | 说明 |
| --- | --- |
| 视频信息解析 | 输入链接，返回标题、封面、时长、作者、可选清晰度列表 |
| 清晰度选择 | 1080p / 720p / 480p / 最佳画质 / 仅音频(MP3) 等 |
| 视频下载 | 服务端下载并合并（高清视频流 + 音频流），再提供给用户 |
| 下载进度 | 实时展示百分比、速度、预计剩余时间 |
| 文件下载 | 完成后浏览器触发下载，临时文件随后清理 |
| 商业化 UI | 浅色蓝调商业风格，含定价区块（视觉展示）、FAQ、免责声明 |
| 响应式 | 桌面与移动端浏览器均可正常使用 |

### 4.2 非功能需求

- **轻量无数据库**：任务进度用内存管理，临时文件用完即清理。
- **技术栈以 Python 为核心**（下载能力），前端为 React 工程。
- **最小改动**：直接封装 yt-dlp 的 Python API，不修改开源源码。
- **友好错误提示**：无效链接 / 不支持站点 / 解析失败等返回中文提示。

## 5. 不在本期范围（后续可扩展）

- 真实**支付/会员/账号体系**（需要数据库与登录，违背"无数据库、轻量"设定）。
- **AI 视频总结、字幕翻译**（需接入大模型 API）。
- **批量下载队列、历史记录持久化**（需数据库）。
- 需要登录态 / 会员 / 受 DRM 保护的内容下载（yt-dlp 能力边界外）。

## 6. 约束与风险

- 部分平台需登录、会员或受 DRM 保护的内容**无法下载**，属预期范围外。
- 高清下载依赖 **ffmpeg** 做音视频合并：本项目用 `imageio-ffmpeg` 自带二进制规避手动安装。
- 服务端下载会占用服务器带宽与临时存储，需做**临时文件清理**。
- **合规性**：仅供个人合规使用，前端需展示**免责声明**。

## 7. 验收标准

- 输入主流平台公开视频链接，可成功解析出信息与清晰度。
- 选择清晰度后可完整下载，文件可正常播放（音视频合并正确）。
- 进度条实时更新，完成后可触发浏览器下载。
- 桌面与移动视口下 UI 表现正常、风格符合商业化定位。

## 8. 平台兼容性现状（持续更新，2026-06-12）

> 核心目标：尽量"免登录、免 Cookie"下载主流平台。下表记录各平台的实测结论，
> 详细技术根因与解决方案见《方案设计》第 10 节。

| 平台 | 现状 | 说明 |
| --- | --- | --- |
| 直链 MP4 / HLS | ✅ 已通过 | 实测：`sample-5s.mp4` 解析+下载，ffprobe 校验 h264+aac 1080p 正常 |
| 抖音 Douyin | ✅ 已解决并实测 | 关键是 URL 规范化：`jingxuan?modal_id=ID` 等链接 yt-dlp 不识别，需转为 `/video/{id}`；规范化后**免 Cookie** 解析下载。实测 720p hevc+aac 合并正常 |
| TikTok | ✅ 实测可用 | 免 Cookie。实测 1080p/720p hevc+aac 合并正常 |
| 哔哩哔哩 Bilibili | ✅ 已解决并实测 | **免 Cookie 打通**（解析→下载→合并→可播放，ffprobe 校验 av1+aac 正常）。根因不是 UA，而是：① yt-dlp 把已签名的 playurl `query` 二次编码破坏 WBI 签名；② Referer 指向被风控的 `/video/` 页面会 412。运行时 monkeypatch 已修复，详见《方案设计》10.2。免登录最高约 480p/720p（更高码率需会员） |
| YouTube | ⛔ 本期不支持（已知限制） | "确认你不是机器人"人机验证（IP 信誉级），免 Cookie 无法绕过。已保留 Cookie 兜底与友好中文提示；本轮不投入攻坚 |
| 西瓜 Ixigua | ⚠️ 需 Cookie | 已加 URL 规范化（`m.ixigua.com/dx/{id}` 等 → `www.ixigua.com/{id}/`），提取器明确要求 Cookie（即便非登录态）。放置 `cookies/ixigua.txt` 后可用 |
| X / Twitter | ⏳ 待验证 | 普通公开视频推文（`/status/{id}`）提取器路径存在；直播 broadcast 链接会慢/超时（已加 `socket_timeout` 防挂起）。需有效公开普通视频推文复验 |
| 快手 / 微博 / Instagram | ⚠️ 多需 Cookie | 快手/微博网页取流需携带 Cookie；Instagram 多需登录。已加快手短链跟随与 cookie 友好提示；Cookie 基础设施就绪，放置对应 `cookies/<平台>.txt` 后可用 |

### 重要决策：尽量不依赖 Cookie

用户明确反馈"使用 Cookie 方式非常不便"。因此**优先采用免 Cookie 的技术手段**
（URL 规范化、开放 API 绕过、浏览器 UA、指纹伪装等）。Cookie 仅作为兜底能力保留
（代码已支持 `backend/cookies/<平台>.txt` 与环境变量），不作为主路径。
